# 证据规则

实证研究、数据构建和形式模型验证的完整设计台账读取 [设计与有效性](design-validity.md)。

## 来源层级

- **直接来源**：原始文献、实际数据、执行日志、代码和配置。用于支持事实与定量主张。
- **派生结果**：由直接来源经过已记录计算得到的指标、表格和图形。保留生成入口及输入版本。
- **诊断材料**：错误轨迹、组件行为、覆盖率、资源消耗和中间状态。用于解释机制，不能自动替代主要结果。
- **背景材料**：综述、检索摘要和二手评论。用于发现线索；正式引用前读取原始来源。

来源记录包含路径或 URL、作者或生成工具、版本、读取日期、读取范围和精确定位。本地结构化结果使用 JSON Pointer；文本使用章节、页码或可唯一定位的原文片段。

## 证据等级

| 标记 | 含义 |
|---|---|
| E1 实证结果 | 可复核数据、明确方法、未参与校准的验证样本 |
| E2 校准结果 | 历史样本估计，缺少独立样本验证 |
| E3 情景结果 | 模型与明确参数假设，用于条件性反事实 |
| E4 理论推测 | 具有机制依据，缺少直接数据检验 |

等级由数据、识别条件和验证设计决定。模拟输出保持 E3；增加样本、延长运行或提高精度不改变等级。历史校准只有在独立样本与识别条件满足后才能提升为 E1。结论措辞与等级一致，零结果附区间、最小可检测效应或检验力。

## 主张记录

`assets/research_record.example.json` 展示最小结构。每项主张使用以下状态：

- `supported`：实际来源直接支持当前表述及其范围。
- `contradicted`：实际来源与当前表述冲突。
- `inconclusive`：已有执行或来源不足以判定。
- `unverified`：尚未核对能够决定该主张的来源。

证据角色使用 `primary`、`diagnostic` 或 `contextual`。主要结论需要与主要问题对应的证据；诊断结果用于解释，背景材料用于交代语境。

定量主张保留：

- `object`：测量对象；
- `metric`：指标定义；
- `value`：来源中的数值；
- `unit`：计量单位；
- `denominator`：比例或汇总的分母；
- `comparison`：比较对象及差值方向；
- `population_or_window`：总体、数据集或时间范围；
- `statistical_unit`：独立性或聚类分析采用的单位。

## 边界与缺失

遵守项目规定的数据、时间窗、隐私和外部传输边界。无法读取的来源保持未核实状态，不根据标题、摘要或相似研究补齐内容。开发集、内部留出集和独立样本外证据分别命名。

历史验证只使用当时已经公开的数据和文件。按发布或申报可用时间与版本标识过滤，不只按观察期间过滤。当前数据库返回内容可能包含后续重述，未经筛选不能用于重建历史信息集。原始版本与修订版本的选择规则在分析前固定，并保留全部版本标识。插值形成的观测不能进入独立留出评价。

失败、缺失和不可评价项保留原状态。跨条件比较采用共同可评估样本，并报告排除造成的剩余偏差。不得删除负向结果以改善表面结论。结构化检查只验证记录契约和本地引用，不代替来源内容审阅。

## 审查输出

审查发现包含严重程度、来源定位、实际证据、影响的具体主张和修复动作。软件检查通过与研究结论成立分别报告；未检查项目标为未知。结构化检查器只验证记录契约和本地 JSON 引用，不代替来源内容审阅。
